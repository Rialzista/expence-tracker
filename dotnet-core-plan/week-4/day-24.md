# День 24 — CORS для SPA-фронтенда

**Неделя:** 4 — Auth, тесты, деплой, склейка с frontend
**Цель дня:** настроить CORS правильно — самый частый источник "непонятных" ошибок при первом подключении SPA к .NET API.

## Темы
- Что такое CORS и почему браузер блокирует запросы с другого origin (Angular/React dev-server на другом порту)
- Настройка через `AddCors` / `UseCors`: allowed origins, methods, headers
- Разница между широкой политикой ("разрешить всё" — только для разработки) и строгой (production)
- Preflight-запросы (`OPTIONS`) — что это и почему иногда "висят"

## Практика
- [ ] Настроить CORS-политику, разрешающую origin локального Angular/React dev-сервера (обычно `localhost:4200` / `localhost:3000` / `localhost:5173`)
- [ ] Проверить, что `app.UseCors(...)` стоит в правильном месте pipeline (до `UseAuthorization`)
- [ ] Смоделировать реальный fetch/HttpClient-запрос из простой HTML-страницы или заготовки фронтенда к API и убедиться, что CORS-ошибки нет

## Что должно получиться к концу дня
API готово принимать запросы с фронтенд dev-сервера без CORS-ошибок в консоли браузера.
