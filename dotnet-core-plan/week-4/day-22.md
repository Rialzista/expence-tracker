# День 22 — JWT-аутентификация

**Неделя:** 4 — Auth, тесты, деплой, склейка с frontend
**Цель дня:** освоить самый частый способ защиты API для SPA-фронтендов.

## Темы
- Как устроен JWT (header/payload/signature), зачем нужен secret/signing key
- Регистрация JWT-аутентификации: `AddAuthentication().AddJwtBearer(...)`
- Генерация токена при логине (claims, expiration)
- `[Authorize]` атрибут на контроллерах/эндпоинтах, `app.UseAuthentication()` + `app.UseAuthorization()` (и важность порядка)

## Практика
- [ ] Добавить простой эндпоинт `/login` (пока с захардкоженным/тестовым пользователем), генерирующий JWT
- [ ] Настроить `AddJwtBearer` с валидацией токена
- [ ] Защитить существующие CRUD-эндпоинты через `[Authorize]`
- [ ] Проверить через Swagger/Postman: без токена — 401, с токеном — доступ есть

## Что должно получиться к концу дня
API выдаёт JWT при логине и требует его для доступа к защищённым эндпоинтам.
