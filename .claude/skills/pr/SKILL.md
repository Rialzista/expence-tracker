# Открытие Pull Request

Команда вызывается вручную:

```
/pr <ветка> "<название PR>"
```

- `$1` — имя ветки, для которой открывается PR. Если ветка ещё не текущая —
  переключиться на неё (`git checkout <ветка>`); если такой локальной ветки
  нет — сообщить об этом и остановиться, новую ветку эта команда не создаёт.
- `$2` — название PR (заголовок). Если аргумент не передан — предложить
  заголовок на основе коммитов ветки и подтвердить его с пользователем,
  а не придумывать и сразу использовать.

Если аргументы не переданы вовсе — спросить пользователя, для какой ветки
и с каким названием открыть PR, не гадать.

## 1. Проверки перед PR

- `git status` — незакоммиченных изменений быть не должно; если есть,
  сообщить пользователю и остановиться (не коммитить и не стешить
  самовольно).
- Ветка не `main` — в `main` PR из самого `main` не открывается.
- Ветка создана от актуального `main` (нет расхождения, которое приведёт
  к конфликтам) — если `main` ушёл вперёд, предупредить пользователя,
  что стоит сделать `git rebase main` или `git merge main` перед PR,
  и спросить, делать ли это.

Чек-лист, как перед коммитом (см. skill `commit`):

```bash
pnpm lint && pnpm typecheck && pnpm test
```

Если в ветке менялся `apps/api` — ещё и:

```bash
pnpm db:up && cd apps/api && pnpm test:e2e
```

Чек-лист не проходит — PR не открывается, ошибки чинятся или сообщаются
пользователю.

## 2. Пуш ветки

```bash
git push -u origin <ветка>
```

Если у ветки уже есть upstream и она не разошлась с origin — обычный
`git push` без `-u`.

## 3. Тело PR

Собрать по всем коммитам ветки, которых нет в `main`
(`git log main..<ветка>`), не только по последнему коммиту. Тело — на
русском, по формату:

```
## Что сделано

- <краткие пункты по сути изменений, не список файлов>

## Как проверить

- [ ] <пункты чек-листа, актуальные для этого PR>
```

## 4. Создание PR

```bash
gh pr create --title "<название PR>" --base main --head <ветка> --body "$(cat <<'EOF'
<тело PR из шага 3>
EOF
)"
```

## 5. Результат

Вернуть пользователю ссылку на созданный PR (`gh pr create` выводит её
в stdout). Не мержить и не аппрувить PR — это отдельное действие,
выполняется только по явной просьбе.
