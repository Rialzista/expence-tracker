# Standup-отчёт

Команда вызывается только вручную (`/standup`), когда пользователю нужно
коротко рассказать, что было сделано за вчерашний рабочий день. Отчёт
выводится прямо в чат текстом, коротко — файл не создаётся, если
пользователь явно не попросил его сохранить.

## 1. Определить диапазон "вчера"

```bash
date +%u        # 1 = понедельник … 7 = воскресенье
date +%F        # текущая дата, для заголовка отчёта
```

"Вчера" — предыдущий календарный день, кроме случая, когда сегодня
понедельник: тогда последний рабочий день — пятница, и диапазон
растягивается на пятницу–воскресенье, чтобы захватить работу выходных,
если она была.

- Сегодня понедельник (`%u` = 1): `--since="4 days ago 00:00" --until="today 00:00"`.
- Иначе: `--since="yesterday 00:00" --until="today 00:00"`.

## 2. Определить, чьи коммиты собирать

Автор — текущий git-пользователь именно этого репозитория, не email из
системного контекста (они могут не совпадать):

```bash
git config user.email
```

## 3. Понять, что было сделано

```bash
git log --all --author="<email>" --since=<since> --until=<until>
```

Обязательно `--all` — работа могла остаться в ещё не смёрженной
feature-ветке. Цель — уловить общую суть дня (какие модули/фичи двигались,
что чинилось), а не собрать инвентарный список коммитов: итоговый отчёт не
должен перечислять коммиты, хэши или конкретные файлы — только общий смысл
проделанной работы. Тела коммитов (текст после заголовка) — уже готовое
"почему", использовать их, а не придумывать причины заново.

## 4. Проверить смёрженные PR (если у репозитория есть GitHub-remote)

```bash
git remote -v
```

Если remote на GitHub есть — дополнительно:

```bash
gh pr list --state merged --search "merged:>=<since-date> author:@me" \
  --json number,title,mergedAt,url
```

Если remote нет — пропустить этот шаг и строить отчёт только по
git-истории.

## 5. Вывести отчёт

Свободный текст на русском, **пара абзацев, без списков и без хэшей
коммитов**:

- Первый абзац — что в целом было сделано за вчера: какая функциональность
  появилась, что чинилось, в каких частях системы (`api`/`web`/`shared`
  — на уровне пакета, не файлов), и вкратце зачем, если это ясно из
  сообщений коммитов.
- Второй абзац (по желанию) — итог: смёрженные PR/ветки, общее ощущение
  от объёма и направления работы за день.

Если за вчера коммитов не найдено — сказать об этом одной фразой, не
выдумывать отчёт.
