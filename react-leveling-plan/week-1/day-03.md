# День 3 — useMemo, useCallback, React.memo

**Неделя:** 1 — Хуки на новом уровне, TypeScript, тулинг
**Цель дня:** понять хуки производительности и, что важнее, понять когда их **не** нужно использовать.

## Темы
- `useMemo` — мемоизация вычисляемого значения (аналог `computed` в других фреймворках)
- `useCallback` — мемоизация функции, чтобы не создавать новую ссылку на каждый рендер
- `React.memo` — предотвращение ре-рендера компонента при неизменных props
- Главная ловушка: преждевременная оптимизация — эти хуки сами по себе не бесплатны, использовать не "на всякий случай", а когда есть реальная проблема (измеримая через React DevTools Profiler)

## Практика
- [ ] Создать сценарий с "тяжёлым" вычислением в рендере, обернуть в `useMemo`, замерить разницу через React DevTools Profiler
- [ ] Создать родительский компонент, который ре-рендерит дочерний из-за новой ссылки на callback — исправить через `useCallback` + `React.memo`
- [ ] Намеренно убрать `useMemo` там, где вычисление дешёвое, и убедиться, что разницы в производительности нет (чтобы прочувствовать, когда оптимизация не нужна)

## Что должно получиться к концу дня
Понимание, что эти хуки — инструмент решения конкретной измеренной проблемы, а не дефолтная практика на каждый компонент.
