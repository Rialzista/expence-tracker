# День 11 — TanStack Query: основы

**Неделя:** 2 — State management и работа с данными
**Цель дня:** освоить главный инструмент работы с серверными данными в современном React — это меняет подход куда сильнее, чем кажется на первый взгляд.

## Темы
- Ключевая идея: **серверный** state (данные с API) — не то же самое, что **клиентский** state (Zustand/Redux) — у него своя специфика: кэш, устаревание, синхронизация
- `useQuery` — fetching с автоматическим кэшированием, `queryKey`, `queryFn`
- `useMutation` — создание/изменение/удаление данных
- `QueryClient`/`QueryClientProvider` — настройка на уровне приложения
- Сравнение с Angular: это концептуальный аналог того, что в Angular-мире иногда делают через RxJS + собственный кэш-слой вручную, только из коробки и декларативно

## Практика
- [ ] Подключить TanStack Query к приложению, обернуть в `QueryClientProvider`
- [ ] Заменить ручной `useEffect + fetch + useState(loading/error/data)` на `useQuery` — увидеть, насколько меньше кода и меньше багов (гонки запросов, забытый loading state)
- [ ] Реализовать `useMutation` для создания записи, с инвалидацией соответствующего query после успеха (`invalidateQueries`)

## Что должно получиться к концу дня
Полный переход от ручного fetch-паттерна на `useEffect` к декларативному `useQuery`/`useMutation`.
