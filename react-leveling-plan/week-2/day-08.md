# День 8 — Context API

**Неделя:** 2 — State management и работа с данными
**Цель дня:** освоить встроенный механизм передачи данных вглубь дерева компонентов без prop drilling.

## Темы
- `createContext`, `Provider`, `useContext` — что это решает (prop drilling)
- Ключевая ловушка: любое изменение значения в Context ре-рендерит **всех** подписчиков — почему Context не замена полноценному state-менеджеру для часто меняющихся данных
- Паттерн разделения Context на несколько (например, отдельно для редко меняющихся настроек и отдельно для часто меняющегося state)
- Сравнение с Angular DI: Context — это про передачу **данных** вниз по дереву, а не про инъекцию **сервисов** (хотя иногда используется и для этого)

## Практика
- [ ] Создать Context для темы приложения (light/dark), Provider на верхнем уровне, использовать в нескольких вложенных компонентах через `useContext`
- [ ] Создать Context для часто меняющихся данных (например, счётчик) и через React DevTools Profiler увидеть, что ре-рендерятся все подписчики при каждом изменении
- [ ] Разделить один "толстый" Context на два — убедиться, что лишние ре-рендеры ушли

## Что должно получиться к концу дня
Понимание, когда Context — это правильный инструмент, а когда нужен полноценный state-менеджер (темы следующих двух дней).
