# День 24 — Производительность: code splitting, Suspense, лишние ре-рендеры

**Неделя:** 4 — Тестирование, производительность, капстоун
**Цель дня:** закрыть тему производительности на уровне приложения, а не отдельного компонента (в отличие от дня 3).

## Темы
- Code splitting через `React.lazy` + `Suspense` — разбивка бандла по роутам/тяжёлым компонентам
- `Suspense` как общий механизм ожидания (используется и для lazy-компонентов, и для данных в связке с некоторыми библиотеками)
- Поиск лишних ре-рендеров через React DevTools Profiler на уровне всего приложения, не одного компонента
- Анализ размера бандла (`vite-bundle-visualizer` или аналог) — что реально "весит" в production-сборке

## Практика
- [ ] Разбить приложение на chunks через `React.lazy` для тяжёлых/редко используемых страниц, обернуть в `Suspense` с fallback
- [ ] Прогнать Profiler на всём приложении в реальном сценарии использования (не синтетический пример), найти и исправить хотя бы один лишний ре-рендер
- [ ] Проанализировать production-бандл, определить самую тяжёлую зависимость

## Что должно получиться к концу дня
Приложение с осмысленным code splitting и хотя бы одним найденным и исправленным реальным performance-issue.
