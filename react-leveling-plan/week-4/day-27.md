# День 27 — Капстоун: основные фичи

**Неделя:** 4 — Тестирование, производительность, капстоун
**Цель дня:** реализовать основной функционал капстоуна.

## Практика
- [ ] Список данных — Server Component с осознанно выбранной стратегией рендеринга (SSR/ISR)
- [ ] Форма создания/редактирования — RHF + Zod, отправка через Server Action или TanStack Query mutation (в зависимости от архитектуры)
- [ ] Клиентские интерактивные части (фильтры, сортировка) — Client Component с Zustand/RTK для UI-state
- [ ] Минимум 2-3 юнит/интеграционных теста на ключевые компоненты (RTL + MSW)
- [ ] Базовая обработка ошибок (401 → редирект на логин, ошибки валидации API → отображение в форме)

## Что должно получиться к концу дня
Работающий end-to-end сценарий: логин → просмотр данных → создание/редактирование → корректная обработка ошибок, покрытый хотя бы минимальными тестами.
