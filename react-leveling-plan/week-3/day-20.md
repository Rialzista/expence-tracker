# День 20 — SSR/SSG/ISR: стратегии рендеринга

**Неделя:** 3 — Формы и Next.js
**Цель дня:** понять, какие есть стратегии рендеринга страницы и когда какую выбирать — частый вопрос на собеседованиях по Next.js.

## Темы
- SSR (Server-Side Rendering) — рендер на каждый запрос
- SSG (Static Site Generation) — рендер на этапе сборки, отдаётся статика
- ISR (Incremental Static Regeneration) — статика, которая обновляется по таймеру/по запросу без полного ребилда
- Как это настраивается в App Router: `fetch` с опциями кэширования (`cache: 'force-cache'` vs `'no-store'`, `next: { revalidate: N }`)

## Практика
- [ ] Настроить одну страницу как полностью статическую (SSG) — данные не меняются между запросами без ребилда
- [ ] Настроить другую страницу с ISR (`revalidate: 60`) — проверить, что данные обновляются раз в минуту
- [ ] Настроить третью страницу с SSR (`cache: 'no-store'`) — данные всегда свежие
- [ ] Для себя сформулировать критерий выбора: какие данные вашего капстоун-проекта под какую стратегию подходят

## Что должно получиться к концу дня
Осознанный выбор стратегии рендеринга под конкретный тип данных, а не "всё по умолчанию".
