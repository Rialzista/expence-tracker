# День 18 — Server Components vs Client Components

**Неделя:** 3 — Формы и Next.js
**Цель дня:** разобраться в главном концептуальном сдвиге последних лет в React — том, чего в вашем предыдущем опыте с React почти наверняка не было.

## Темы
- По умолчанию все компоненты в App Router — **Server Components**: рендерятся на сервере, не отправляют JS в браузер, не могут использовать хуки/browser API
- `'use client'` директива — где начинается "обычный" React, который вы знаете (хуки, интерактивность, event handlers)
- Композиция: Server Component может рендерить Client Component (но не наоборот напрямую — только через `children`/props)
- Зачем это нужно: меньше JS на клиенте, прямой доступ к бэкенду/БД из компонента без отдельного API-слоя

## Практика
- [ ] Написать Server Component, который делает `await` прямо внутри компонента (например, к mock-функции, имитирующей запрос к БД)
- [ ] Попробовать использовать `useState` в Server Component — увидеть ошибку, понять почему
- [ ] Вынести интерактивную часть в отдельный Client Component (`'use client'`), встроить его в Server Component
- [ ] Осознанно решить для 2-3 компонентов приложения: должен ли он быть Server или Client, и почему

## Что должно получиться к концу дня
Чёткое понимание границы Server/Client Components и осознанный выбор, а не "везде 'use client' на всякий случай".
