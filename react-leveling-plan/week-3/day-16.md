# День 16 — Валидация форм (Zod/Yup)

**Неделя:** 3 — Формы и Next.js
**Цель дня:** освоить schema-based валидацию — более декларативный подход, чем ручные валидаторы.

## Темы
- Zod (или Yup) — описание схемы данных, из которой автоматически выводится TypeScript-тип (`z.infer<typeof schema>`)
- Интеграция с RHF через `zodResolver`/`yupResolver`
- Кастомные правила валидации, кросс-полевая валидация (например, "подтверждение пароля")
- Сравнение с Angular: `Validators.required`/кастомные Validators ↔ Zod-схема — в Zod валидация и типизация выводятся из одного источника

## Практика
- [ ] Описать Zod-схему для формы из дня 15, вывести TypeScript-тип через `z.infer`
- [ ] Подключить `zodResolver` к `useForm`, убедиться что ошибки валидации отображаются
- [ ] Добавить кросс-полевое правило (например, дата окончания не раньше даты начала)
- [ ] Убедиться, что типы формы и Zod-схемы не расходятся (единый источник правды)

## Что должно получиться к концу дня
Форма с полной schema-based валидацией, где типы и правила валидации не дублируются вручную.
