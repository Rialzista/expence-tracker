# Чек-лист код-ревью

Список специфичных для проекта правил, которые не ловятся линтером/тайпчекером
автоматически и которые легко нарушить по невнимательности. Общие вещи вроде
чистоты кода, читаемости, отсутствия мёртвого кода — само собой разумеются и
здесь не перечисляются. Источник — `CLAUDE.md` в корне, `apps/api/CLAUDE.md`,
`apps/web/CLAUDE.md`.

## Коммиты и PR

- [ ] Заголовок коммита — Conventional Commits, на русском, в повелительном
      наклонении («добавить», а не «добавил»/«добавляет»), без точки в конце,
      до 72 символов.
- [ ] Тип коммита соответствует сути изменения: `feat`/`fix`/`refactor`/`test`/
      `docs`/`chore`/`perf`. `refactor` не должен менять поведение.
- [ ] Область (`api`/`web`/`shared`/`config`/`claude`) указана верно или
      осознанно опущена для изменений по всему монорепо.
- [ ] Тело коммита объясняет «почему», а не пересказывает дифф — альтернативы,
      которые отпали, и осознанно проведённые границы задачи.
- [ ] Коммит — законченная единица работы, собирается и проходит тесты сам по
      себе (нет коммитов вида «на будущее»).
- [ ] Ветка названа `<тип>/<краткое-описание-через-дефисы>` на английском,
      создана от актуального `main`.
- [ ] Нет прямых коммитов в `main` — только через PR.
- [ ] Перед PR прогнаны `pnpm lint && pnpm typecheck && pnpm test`; при
      изменениях в `apps/api` — ещё и `pnpm db:up && pnpm test:e2e`.

## Контракты (packages/shared)

- [ ] Новый/изменённый DTO — это одна Zod-схема в
      `packages/shared/src/schemas/*.schema.ts`, экспортированная из
      `packages/shared/src/index.ts`, а не отдельные типы на фронте и бэке.
- [ ] На бэке схема подключена через `ZodValidationPipe`
      (`apps/api/src/common/pipes/`), а не через ручную валидацию тела запроса.
- [ ] На фронте та же схема используется через `zodResolver` в React Hook Form
      (или явно обёрнута собственной схемой формы — см. пункт про
      `create-transaction` в разделе web ниже).
- [ ] Типы DTO берутся через `z.infer` от схемы, а не дублируются вручную.

## Зафиксированные версии — не трогать без явной причины

- [ ] `prisma`/`@prisma/client` в `apps/api/package.json` — ровно `7.10.0`,
      без каретки (тег `latest` в npm указывает на `8.0.0-rc`).
- [ ] `typescript` — `~6.0.3` во всём монорепо, не 7.x (`@nestjs/cli@12` и
      `typescript-eslint@8` требуют TS < 6.1).
- [ ] `nestjs-zod` не добавлен как зависимость (peer-конфликт с Nest 12).

## apps/api

- [ ] В сервисах/контроллерах с DI импорты классов-зависимостей в конструкторе
      — value-импорты (`import { X }`), не `import type { X }` — иначе Nest
      получит `Object` вместо класса в рантайме. `eslint --fix` это не чинит
      корректно, проверять глазами.
- [ ] Не добавлены `class-validator`/`class-transformer`, не используется
      Nest'овский `ValidationPipe` — только `ZodValidationPipe`.
- [ ] Новые типы ошибок проходят через общий `HttpExceptionFilter`, а не
      возвращают свой формат ответа в обход него.
- [ ] Строка подключения к БД не захардкожена и не читается напрямую из
      `process.env` в обход `ConfigService`/`prisma.config.ts`.
- [ ] Новые защищённые роуты не забыли `JwtAuthGuard` (он глобальный через
      `APP_GUARD`); публичные роуты явно помечены `@Public()`, а не
      случайно открыты отсутствием гварда.
- [ ] Идентификатор пользователя берётся через `@CurrentUser()`, а не
      напрямую из `req.user`.
- [ ] Межмодульное взаимодействие — через CQRS (`CommandBus`/`QueryBus`),
      **нет** прямого импорта `Service`/`Repository` чужого модуля
      (`UsersService`, `CategoriesService`, `TransactionsService` наружу не
      экспортируются). Наружу модуль отдаёт только классы команд/запросов/
      событий.
- [ ] `CqrsModule.forRoot()` не продублирован в другом модуле — вызывается
      ровно один раз, в `app.module.ts`.
- [ ] Проверка существования связанной сущности из чужого модуля (например,
      `categoryId` в транзакции) идёт через Query, которая возвращает `null`
      при отсутствии — решение о 404 принимает вызывающая сторона, а не сам
      Query-хендлер.
- [ ] Новые переменные окружения добавлены в Zod-схему
      `apps/api/src/config/env.schema.ts`, а не читаются как «сырые» строки
      без валидации.
- [ ] После изменения `prisma/schema.prisma` клиент пересоздан
      (`pnpm db:generate`), актуальная генерация закоммичена/не забыта.
- [ ] После изменения методов — актуализирован/добавлен JSDoc; у методов
      контроллеров — декораторы Swagger (`@ApiOperation`/`@ApiResponse`).
      На DTO (`z.infer` от Zod-схем) это не распространяется — вешать
      `@ApiProperty` там не на что.

## apps/web

- [ ] `next.config.ts` остаётся CJS-совместимым — без `import.meta` (ломает
      сборку конфига в ESM-бандл).
- [ ] `settings.react.version` в eslint-конфиге не менялся на `'detect'`.
- [ ] Новый vitest-конфиг — с расширением `.mts`, не `.ts`.
- [ ] Новые компоненты shadcn/ui добавлены через `pnpm dlx shadcn add`, а не
      скопированы руками — и лежат в `src/shared/ui`.
- [ ] Новый код в зоне FSD (`entities`, `features`, `widgets`, `shared/ui`)
      соответствует слоям: доменные хуки/данные — в `model/`, вёрстка — в
      `ui/`, бизнес-правила не текут в `ui/`-компоненты.
- [ ] Нет новых прямых импортов между `features`/`widgets` в обход
      `entities`/`shared` (кроме уже зафиксированного осознанного исключения
      `lib/api-client.ts → entities/session`).
- [ ] Код вне FSD (`src/lib/*`, `src/stores/ui-store.ts`, старые страницы
      `(dashboard)/transactions|categories|stats`) не мигрируется попутно в
      рамках несвязанной задачи — технический долг зафиксирован осознанно,
      выносится отдельной задачей.
- [ ] Формы с `<input type="date">` не используют DTO-схему из `shared`
      напрямую, если бэкенд ждёт полный ISO 8601, а input отдаёт `YYYY-MM-DD`
      — нужна собственная схема формы (см. `create-transaction-form.tsx`).
- [ ] Компоненты, читающие защищённые данные (токен, TanStack Query к API),
      помечены `'use client'` — на сервере (RSC) `accessToken` всегда `null`.
- [ ] Не добавлены сторонние date-библиотеки — форматирование дат через
      `Intl.DateTimeFormat`.
- [ ] Цвет/знак суммы транзакции определяется по полю `type`, а не по знаку в
      строке `amount`.
- [ ] `pnpm typecheck` реально прогнан как `next typegen && tsc --noEmit`
      (голый `tsc --noEmit` без предварительного `next dev/build/typegen`
      упадёt на несуществующих типах вроде `LayoutProps`).

## pnpm / инфраструктура

- [ ] Новая зависимость с postinstall-скриптом явно прописана в `allowBuilds`
      в `pnpm-workspace.yaml` (`true`/`false`), а не молча блокируется/
      разрешается по умолчанию.
